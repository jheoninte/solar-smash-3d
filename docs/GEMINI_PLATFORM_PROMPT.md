# Gemini 작업: 영구 저장과 플랫폼 서비스 경계

> 이 요청은 Codex 통합과 Windows 검증을 완료했다. 아래는 원래 구현 명세의 기록이다. 재생성된 소스는 최신 통합 상태이며 같은 작업을 다시 수행하지 않는다. 현재 동작과 제한은 `docs/PLATFORM_SERVICES.md`를 기준으로 한다.

이 문서 다음에 현재 프로젝트의 관련 파일 전체가 붙는다. 이 소스만 기준으로 구현하라. ZIP 접근이나 과거 코드, 읽지 않은 게임 스킬을 검토했다고 가정하지 마라. 소스가 누락되어 판단할 수 없다면 누락 파일명을 먼저 명시하라.

목표는 Windows에서 Three.js 게임을 계속 개발하면서 iOS 우선 출시용 플랫폼 서비스 계층을 준비하는 것이다. 큰 코드 초안을 Gemini가 작성하고 Codex가 통합·검증한다. 최종 Xcode·서명·iPhone·TestFlight 검증만 Mac에서 수행한다.

## 이번 구현 범위

1. `src/platform/`에 플랫폼 감지, 저장 어댑터, 서비스 진입점을 구현하라. 게임 코어가 네이티브 SDK를 직접 참조하지 않도록 의존성을 주입하라.
2. 브라우저는 기존 localStorage 키 `solar-smash-3d.save`를 유지한다. 네이티브는 공식 `@capacitor/preferences`의 JSON 저장을 사용한다. 설치할 정확한 호환 버전과 변경한 package.json을 제시하고, 잠금 파일은 Codex가 npm으로 생성한다. CDN/원격 서버·Firebase·유료 플러그인은 도입하지 마라.
3. 네이티브 저장이 없고 같은 WebView의 기존 localStorage에 유효한 세이브가 있을 때만 한 번 이전한다. 네이티브에 기존 데이터가 있으면 우선하며, 저장 실패/파싱 실패를 데이터 없음으로 취급해서 덮어쓰지 마라. 이전 성공 전후에도 기존 localStorage를 삭제하지 마라. Windows 브라우저에서 iPhone으로 사용자 세이브가 자동 전송된다고 설명하지 마라.
4. 네이티브 저장은 비동기다. 저장 요청 시점의 JSON 스냅샷을 순서대로 처리해 오래된 쓰기가 최신 상태를 덮어쓰지 않게 하라. 실패한 쓰기 하나가 다음 요청을 막지 않아야 한다. `persist()`가 Promise를 반환하면 모든 소비자의 boolean 성공 판정도 함께 수정하라. Promise 자체를 성공으로 취급하거나 완료 전 저장 성공을 표시하면 안 된다.
5. 미션·상점의 메모리 상태 변경과 중복 방지는 동기적으로 먼저 처리하라. 비동기 저장 대기 때문에 타격 갱신/발사체 순회가 깨지거나 빠른 연속 구매·보상 수령이 중복되지 않아야 한다. 잔액+소유, 완료 ID+보상은 각각 하나의 스냅샷에 저장하라. 저장 대기/성공/실패를 UI에 정확히 반영하고, 실패해도 게임은 계속 실행한다. 페이지 종료 이벤트에서 비동기 저장 완료를 보장한다고 주장하지 마라.
6. 결제·광고·랭킹은 이번에 실제 연동하지 않는다. 앞으로 교체할 최소 인터페이스만 만들고 기본 구현은 `{ status: 'unavailable' }`처럼 명확히 반환하라. 네이티브 실행 여부만으로 결제/광고/랭킹이 지원된다고 판단하지 마라. 구매 성공·광고 보상·권한을 만들어내지 말고 미지원 상품 UI도 노출하지 마라.
7. Capacitor core와 Preferences가 브라우저에서 해석되도록 현재 정적 ESM/import map·dev server·build 경로를 함께 처리하라. Vite로 전면 교체하지 마라. `node_modules` 경로를 배포 런타임에서 참조하지 마라. 필요한 로컬 벤더 파일과 라이선스 포함, 직접 루트 진입과 하위 경로 진입을 모두 고려하라.

## 반드시 유지할 실제 구조

- `GameStateStore.loadGame()`은 state를 반환한다. `store.state`는 없다.
- 스키마 v4: `mode, weapon, stats, session.recentImpacts, progression: { coins, completedMissions, ownedSkins, equippedSkin }`. v2/v3 이전과 손상 필드 정규화를 보존한다.
- 최근 120 타격을 전체 모드에서 유지하며 복원 시 데미지/보상을 재발행하지 않는다. `runId`는 저장하지 않는다.
- 미션은 6개, 첫 완료만 보상 지급. Reset은 진행도/소유/장착을 유지한다.
- 상점: earth 기본, obsidian 250, ember 450, aurora 650. 구매/장착 분리, 장착은 외형만 바꾸고 지형을 보존한다.
- `ShopSystem({ state, persist })`를 유지하거나 변경 시 모든 호출부를 함께 제공하라.
- `DestructionEventBus.subscribe('impact', handler)`와 `emitImpact`를 사용한다. 무기 정의는 `WEAPONS`다.
- `main.js`의 완료 큐는 발사체 update가 끝난 뒤 비운다. 이벤트 수신 중 발사체 배열을 비우지 마라.
- `window.HubGame`은 이 게임의 필수 조건이 아니다. 없다고 로컬 저장이나 코인 상점/미션을 차단하지 마라.
- 현재 모달·일시 정지·안전한 DOM 생성·한국어 모바일 UI를 보존한다.
- Capacitor 8.6.2와 Node 22 이상, `webDir: dist`, 루트 직접 진입, 외부 server.url 없음. 임시 앱 ID는 최종 ID가 아니다.

## 출력

변경/신규 파일 목록과 각 파일의 완성된 전체 코드를 경로와 함께 제공하라. 생략·의사 코드·부분 diff는 금지한다. 변경 없는 파일은 재출력하지 마라. 의존성 설치 명령, 영구 저장/이전/실패 처리의 선택 근거, Windows 검증 항목과 Mac에서만 검증 가능한 항목을 구분하라. 테스트를 실행하지 않았다면 실행했다고 하지 마라.

최소 검증 시나리오: 기존 v4 복원, v2/v3 이전, 빈 네이티브 저장 이전, 네이티브 데이터 우선, 손상/읽기 실패 시 덮어쓰기 방지, 느린 연속 저장 순서, 첫 쓰기 실패 후 다음 쓰기 복구, 빠른 중복 구매와 미션 보상, 저장 대기 표시, 브라우저/정적 빌드 실행. 네이티브 기기 테스트는 추후 Mac에서 진행한다.
