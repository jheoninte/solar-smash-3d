# iOS 우선 출시 계획

## 사용자 확정 방향

- 기본 무료 IAP(인앱 구매) + IAA(인앱 광고) 하이브리드 캐주얼 게임.
- iOS를 먼저 출시하고 Google Play로 확장.
- 자체 서버 없이 기본 게임을 오프라인에서 실행. 구매·광고·플랫폼 랭킹 등 온라인 서비스는 연결 가능할 때 이용.
- 출시 시 상점과 광고 제공. Game Center는 경쟁 모드나 업적의 필요성이 확인되면 추가.
- Windows PC에서 Codex와 Gemini로 Mac 인계 직전까지 게임·콘텐츠·UI·플랫폼 서비스 코드를 개발. 최종 iOS 빌드·실기기 검증·TestFlight 단계는 Mac mini에서 계속 진행.
- 대규모 초안은 사용자가 Gemini로 전달하고 Codex가 검토·통합·검증.

## 제안 아키텍처

현재 구현을 활용하는 Three.js + Capacitor를 우선 검증한다. 플랫폼 서비스 경계와 Preferences 저장 어댑터까지 구현했으며 Windows 검증과 Mac 실기기 검증의 구분은 `PLATFORM_SERVICES.md`에 정리했다. 엔진 및 패키징 확정은 iPhone 실기기 검증 이후로 한다. 기존 Godot 자료는 참고 자료로 보존한다.

| 계층 | 책임 |
| --- | --- |
| 게임 코어 | 무기, 파괴 이벤트, 미션, 보상, 진행도. 브라우저·iOS·Android 공용 |
| 렌더링과 입력 | Three.js, 모바일 해상도, 터치, 카메라, 성능 옵션 |
| 플랫폼 서비스 | 광고, 결제, 랭킹, 햅틱, 수명주기, 영구 저장의 인터페이스 |
| 브라우저 어댑터 | 개발용 기능과 미지원 상태. 실제 구매·광고 성공으로 위장하지 않음 |
| iOS 어댑터 | Capacitor 네이티브 브리지, StoreKit, 광고 SDK, 필요 시 Game Center |
| Android 어댑터 | 후속 Play Billing 및 광고 SDK, 필요 시 Play Games |

모든 게임 파일은 앱에 포함한다. 브라우저 미리보기의 localStorage는 현재 개발용 저장이며, iOS에서는 버전 관리된 JSON을 앱 영구 저장 영역으로 옮기는 어댑터와 이전 절차를 검증한다. 구매 권한은 로컬 불리언만으로 판정하지 않고 스토어에서 검증된 거래를 기준으로 한다.

Capacitor core/CLI/iOS 8.6.2와 패키징 설정, 로컬 웹 번들 검증 명령을 준비했다. StoreKit 2와 AdMob iOS 브리지 소스 통합·검토 수정을 완료했으며, 네이티브 프로젝트 생성·Swift 컴파일·실제 SDK/실기기 검증은 아직 수행하지 않았다. 세부 절차는 `NATIVE_HANDOFF.md`를 참고한다. 사용자의 작업 범위에 따라 Windows 개발 중 조기 Mac 전환을 선행 조건으로 요구하지 않는다. WKWebView의 WebGL 성능·GPU 메모리·앱 복귀·오디오·safe area·영구 저장·실제 구매·광고는 Mac 인계 후 iPhone에서 검증한다. Windows 단계의 완료는 Mac 인계 준비 완료를 뜻하며, iOS 출시 검증 완료를 뜻하지 않는다. Mac 검증에서 발견되는 문제는 인계 후 수정한다.

## 재미와 리텐션 개발 기준

- 쉬운 조작과 즉각적인 파괴 피드백을 먼저 완성하고, 30~90초 안에 이해·도전·결과를 경험하는 짧은 미션을 우선 검증한다.
- 목표 달성 → 보상 → 외형·콘텐츠 해금 → 다음 도전의 루프를 만든다. 무료 샌드박스도 유지한다.
- 미션 변주, 명확한 다음 목표, 수집 요소로 재방문 동기를 제공한다. 일일 도전은 서버 시간 없이 구현할 경우 기기 시간 변경 한계를 고려해 가치가 큰 유료 보상과 연결하지 않는다.
- 플레이를 막는 광고보다 사용자가 선택하는 보상 광고를 우선한다. 미션 완료율·반복 플레이·광고 선택률·구매 전환을 향후 검증 지표로 삼되 아직 실측한 것처럼 표현하지 않는다.
- 초기에는 로컬 기록과 플레이테스트로 루프를 검증한다. 외부 분석 SDK·개인정보 수집·통합 랭킹 서비스는 필요성과 비용을 검토한 후 선택한다.

## 초기 수익화 제안

상품과 광고 배치는 아직 확정된 출시 사양이 아닌 개발 제안이다.

상세 기준과 통합 상태는 `MONETIZATION_PLAN.md`에 정리했다. 광고 제거 상품과 선택형 미션 보너스·전면 광고 공통 흐름 및 iOS 어댑터 소스를 통합했다. 기본 상품·광고 ID는 null/off이며 실제 구매·광고 검증은 후속 Mac 단계다. 유료 외형 팩은 별도 후속 범위다.

- 비소모성 IAP: 강제 광고 제거. 복원 버튼과 재설치 후 구매 복원을 제공한다.
- 비소모성 IAP: 외형 스킨·테마 팩. 핵심 파괴 체험은 무료로 플레이할 수 있게 한다.
- 선택형 보상 광고: 미션 완료 보상 추가 수령 또는 무기 일시 체험. SDK의 유효한 보상 이벤트가 확인된 경우에만 한 번 지급한다.
- 전면 광고: 미션 종료 등 명확한 중단 지점에서만 검토한다. 플레이 중 발사·조준을 끊지 않고 첫 세션 유예와 노출 간격을 둔다.
- 광고 제거 상품이 어떤 광고를 제거하는지 구매 화면에 명시한다. 선택형 보상 광고를 남긴다면 선택 사항임을 명확히 한다.
- 초기 버전은 구독·랜덤 유료 상품·판매용 소비 재화를 우선하지 않는다. 우선 단순한 구매 복원과 보상 경제부터 검증한다.
- 광고 미수신·오프라인·구매 취소·보류 상태에서도 게임이 계속 동작해야 한다.

출시 연동 시 StoreKit Sandbox, TestFlight, 광고 테스트 ID로 확인한다. 실결제 상품·실광고 ID·가격·유료 플러그인 계약은 사용자 결정 후 적용한다. 개인정보 처리방침, App Privacy, 광고 동의 흐름을 준비하고 ATT는 실제 추적 사용 여부와 SDK 동작에 맞춰 결정한다.

## 랭킹과 비용

| 선택 | 권장 시점 | 비용과 판단 |
| --- | --- | --- |
| 자체 서버 없음 | 지금부터 | 게임용 서버 월 유지비 없음. 앱스토어 계정·판매 수수료 등은 별도 |
| Apple Game Center | iOS에서 점수 경쟁·업적이 필요해질 때 | 별도 랭킹 서버 사용료 없이 Apple 플랫폼 기능 활용. Apple Developer Program 가입 필요 |
| Google Play Games | Android 출시 시 필요에 따라 | Android용 플랫폼 랭킹·업적. Apple 랭킹과 자동으로 통합되지 않음 |
| Firebase 무료 범위 | 플랫폼을 넘는 통합 랭킹·클라우드 저장 등이 실제로 필요할 때 | 제품별 무료 한도와 요금제가 다름. 순위 집계·조회량·인증·점수 검증 비용을 산정한 뒤 선택 |
| Firebase 유료 또는 별도 검증 서비스 | 무료 범위를 넘거나 구매·점수 검증 요구가 생길 때 | 예상 월 비용, 사용량 한도, 악용 대응을 제시하고 사용자 승인 후 도입 |

초기 최저 비용 경로는 자체 서버 없이 로컬 진행도와 필요한 플랫폼 서비스만 사용하는 것이다. Firebase는 지금 추가하지 않는다. 클라이언트 점수 제출만으로 완전한 부정행위 방지가 되는 것은 아니므로 랭킹 점수는 샌드박스 누적 데미지보다 규칙이 정해진 챌린지 결과를 기준으로 검토한다.

계정 비용 참고: Apple Developer Program은 통상 연 US$99, Google Play Console은 통상 일회 US$25다. 가입 유형·지역·세금·가입 시점에 따라 공식 안내와 실제 청구 금액을 확인한다. 판매 수수료는 별도이며 할인 프로그램 자격을 자동으로 가정하지 않는다. 이 문서에서 최신 요금을 실시간 조회한 것은 아니다.

공식 확인 링크:
- Apple 계정: https://developer.apple.com/programs/whats-included/
- Game Center: https://developer.apple.com/game-center/
- Google Play 계정: https://support.google.com/googleplay/android-developer/answer/6112435
- Firebase: https://firebase.google.com/pricing

## 개발 순서와 완료 조건

1. 플레이 가능한 출시 루프: 샌드박스와 짧은 데이터 기반 미션, 로컬 보상·진행도, 중복 보상 방지. 현재 파괴 체험을 유지한다.
2. Windows 기술 준비: Capacitor 후보 평가, 네이티브 서비스 경계와 패키징 설정 설계, 브라우저 수명주기·리소스 한도·저장 실패 처리 검증. Mac 전환은 이 단계의 선행 조건이 아니다.
3. 모바일 완성도: 터치 카메라, 피드백·사운드·햅틱 설정, safe area, 접근 가능한 조작, 튜토리얼과 콘텐츠.
4. 플랫폼 서비스: 영구 저장·광고·구매·선택적 랭킹 인터페이스 분리. 브라우저 개발 동작과 실제 네이티브 성공 상태를 구분한다.
5. 수익화 코드: 상점 UI, 스토어 상품 조회·현지 가격 표시 경로, 구매·복원·실패 처리, 보상 광고 1회 지급·광고 제거 경로와 플랫폼 브리지 소스 준비. 실제 가격·거래·광고 SDK 동작은 Mac 인계 후 검증한다.
6. Game Center 필요성 결정: 미션 기록이나 업적이 경쟁·재방문에 기여하면 인증·제출·조회와 로그인 실패 처리를 연동한다.
7. Windows 완료 및 Mac 인계: 브라우저 QA, 미완료 네이티브 검증 목록, SDK·상품·광고 설정 안내, 소스와 실행 가이드를 정리한다. 이후 Mac에서 실기기·구매 복원·오프라인·광고 QA, 개인정보 공개 확인, 서명, TestFlight와 심사 제출을 진행한다.
8. Android 확장: 공용 코어 유지, Android 서비스 어댑터, 실제 Play Billing 및 기기 검증, 출시 준비.

## Mac 인계 패키지

`MISSION_REPLAY_PLAN.md`의 미션 별점·로컬 최고기록과 v6 저장을 통합하고 Windows에서 검증했다. 기존 6개 미션·보상 경제를 유지한다. 다음에는 별점 시간 기준과 실제 재도전 동기를 플레이테스트한다. 현재는 로컬 기록으로 목표를 제공하고 Game Center는 추가하지 않는다. 경쟁 수요와 점수 규칙이 확인될 때 별도 결정한다.

스마트폰 편의 개선을 우선해 자동공격 켜기/끄기·조준점·메뉴 진입 시 공격 중지·작은 화면 HUD·상점/결과의 다음 외형 목표를 구현했다. 다음 대규모 작업은 `GEMINI_MOBILE_EXPERIENCE_PROMPT.md`의 레이저 연출·rolling 120타격 성능·Solar 조준 개선이다. 매출이나 리텐션 향상은 아직 측정하지 않았다.

챌린지 확장 후보는 `BALANCE_PLAN.md`에 보류했다. 기존 입문/기록을 보존하고 신규 챌린지 6개·전용 발사 간격·복합 목표·팔레트 외형 3개를 검토한다. 광고 없는 수집 경로와 시간 하한은 `BALANCE_AUDIT.md`에서 계산했으며, 게임에는 아직 적용하지 않았다. 30~90초 체험과 재미는 구현 후 플레이테스트로 검증한다.

검증된 소스·잠금 파일·실행 가이드·데이터 이전 규칙·필요 SDK 목록·미완료 항목을 Git으로 전달한다. 인증서, 비밀 키, 서명 자격 증명은 저장소에 넣지 않는다. Mac에서 Node 의존성 설치, 네이티브 의존성 동기화, Xcode 팀·번들 ID 지정, 실기기 검증, Archive, TestFlight 업로드를 이어간다. 현재는 번들 ID·스토어 상품 ID·광고 단위 ID를 확정하거나 생성하지 않는다.
