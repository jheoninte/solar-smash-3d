# Gemini 구현 요청: 수익화 공통 흐름 1차

**최우선 프로젝트 조건: 독립 iOS 게임이며 HubGame 의존성을 추가하지 않는다. HubGame이 없어도 기존 로컬 저장·코인 상점·미션·오류 안내를 모두 유지한다. 다른 프로젝트나 게임 스킬의 HubGame 전용 규칙을 가져오지 마라.**

뒤에 현재 저장소의 텍스트 소스를 제공한다. ZIP을 열거나 읽지 않은 스킬을 검토했다고 가정하지 마라. 이번 범위는 광고 제거 상품의 구매/복원 상태 처리, 미션 보상 광고와 전면 광고 정책, UI와 보상 중복 방지다. Codex가 결과를 검토·통합·검증한다. 실제 StoreKit/AdMob/동의 SDK 어댑터는 다음 단계이며 이번에 새 네이티브 SDK나 유료 서비스는 설치하지 않는다. 계약과 인터페이스를 구현하고, 실제 플랫폼은 unavailable인 상태를 유지하라.

## 이미 동작하는 코드: 덮어쓰지 말 것

- Three.js 0.160, Capacitor core/CLI/iOS 8.6.2, Preferences 8.0.1, Haptics 8.0.2, Node 22, 정적 ESM/import map, webDir=dist다. Vite·CDN·런타임 node_modules 접근은 없다.
- `GameStateStore.loadGame()`은 state를 반환한다. `persist()`는 Promise<boolean>이며 동기 상태 변경 후 스냅샷을 순차 저장한다. ShopSystem과 claimMissionReward의 즉시 결과에 있는 `whenSaved`로 실제 완료를 기다린다. Promise를 성공 boolean으로 사용하지 마라.
- `createPlatform()`은 한 번만 생성하고 storage를 게임/설정에 공유한다. Payments/ads/ranking은 미지원 상태이고 haptics는 실제 등록된 네이티브 플러그인만 사용한다.
- `StorageAdapter.load(key,{validate})`는 기본으로 게임 v2/v3/v4 형식을 검증하고 별도 설정 형식을 주입받는다. 읽기 실패/미래 버전은 빈 데이터가 아니다. 원본 덮어쓰기를 차단한다. 키별 보호와 공유 큐를 보존한다.
- 별도 설정 키 `solar-smash-3d.settings.v1`의 음소거/0~1 음량/햅틱/안내 완료, 탭/드래그/핀치 입력, 카메라/사운드/리소스 정리를 유지한다.
- 설정·안내는 미션을 보존한 채 정지한다. 상점·미션 목록은 런을 종료한다. 미션 완료 처리는 weapons.update/이벤트 순회가 끝난 뒤다. runId는 임시이며 저장하지 않는다.
- HubGame은 로컬 저장·상점·미션의 조건이 아니다. 없다고 폴백을 막거나 오류 안내 DOM을 제거하지 마라. 이 요청은 과거의 HubGame 차단 지침을 사용하지 않는다.
- 기존 무료 코인 외형 4종·가격·파괴 지형·6개 미션·첫 완료 보상은 유지한다. 유료 외형, 구독, 판매용 코인, 랭킹, 분석 SDK는 이번 범위가 아니다.

## 기준과 모듈

`docs/MONETIZATION_PLAN.md`와 `src/game/monetization/config.js`를 기준으로 하라. 정책은 초기 개발값이다. 새 코드 예시는 `MonetizationController`, 순수 `AdPolicy`, 플랫폼 계약/미지원 어댑터로 나눌 수 있다. main.js에는 조립과 결과 콜백만 두고 게임 코어에서 SDK를 import하지 마라.

실제 상품/광고 ID는 null이고 enabled는 false다. iOS/Android 감지만으로 지원되었다고 판단하거나, URL/localStorage/개발 버튼으로 성공 어댑터를 선택하게 만들지 마라. 테스트에서만 주입한 가짜 어댑터로 상태 전이를 검증한다. 배포 경로에서 가짜 구매·보상·권한은 생성하지 않는다.

## 1. 플랫폼 계약과 구매/복원

- 한 가지 일관된 비동기 계약을 정의하라. 상품 조회에는 스토어 상품 ID·현지 표시 가격·구매 가능 여부를, 구매에는 success/cancelled/pending/unavailable/error를 구분한다. success는 검증된 비소모성 권한 결과가 함께 있어야 한다.
- `restore()`와 `getEntitlements()` 및 추후 거래 업데이트를 받을 구독 경로를 준비한다. 미지원 어댑터는 available/success/소유권을 생성하지 않는다. pending이나 unverified를 성공으로 처리하지 마라.
- 권한 미확인과 소유하지 않음을 구분한다. 조회 네트워크 오류만으로 기존의 검증된 권한을 지우지 않는다. 검증된 최신 비소유 결과/환불은 반영할 수 있어야 한다. 권한을 단순한 게임/설정 로컬 불리언으로 확정하지 않는다.
- remove_ads는 전면 광고만 제거하며 선택형 보상 광고는 남는다. 상품 ID/현지 가격이 없거나 자동 전면 광고 설정이 비어 혜택을 제공할 수 없으면 판매 상품으로 내지 마라. 임의 가격·가짜 무료 가격·개발용 ID·내부 오류 메시지를 상품 설명에 노출하지 마라.
- 코인 상점과 유료 상품을 구분한다. 미지원이면 기존 코인 상점은 정상 제공하고 유료 영역에는 간결한 이용 불가 안내만 표시한다. 구매/복원 중 버튼 중복 실행 방지와 사용자 취소/보류/오프라인 안내를 제공한다. 미지원 상태의 구매/복원 버튼은 숨기거나 비활성화한다.
- 늦은 상품 조회·구매 콜백으로 닫힌 모달이 다시 열리거나 다른 결과를 덮어쓰지 않게 한다. Promise rejection과 dispose도 처리한다.

## 2. 보상 광고와 게임 저장 v5

- 현재 첫 완료 결과(`isFirst`)가 있고 해당 기본 보상이 `whenSaved=true`로 저장된 뒤에만 보너스 제안을 만든다. 미지원/미준비/동의 불명/읽기 보호/저장 실패 상태에는 광고 선택 버튼을 내지 않는다. 기본 완료 보상은 광고와 상관없이 먼저 지급한다.
- 현재 결과에 '광고를 보고 +N 코인'을 표시하고 기본 보상 50% 내림, 미션별 1회로 고정한다. UI가 전달한 보너스 숫자를 신뢰하지 말고 미션 정의로 계산한다. 재도전·목록·복원·새로고침은 새 제안을 생성하지 않는다.
- 요청 ID와 현재 완료/미션 ID를 연결한다. show 성공/닫힘/시간 경과만으로 지급하지 마라. 어댑터가 유효한 SDK 보상 이벤트를 확인한 경우에만 현재 요청을 한 번 처리한다. 오래된 요청·다른 요청·중복 이벤트를 거부하고, 광고 닫힘과 보상 이벤트의 순서 차이를 계약에서 명시하라.
- 단일 '광고 닫힘' Promise로 보상 이벤트를 놓치거나, 임의 타이머로 성공을 추정하지 마라. 다음 네이티브 어댑터가 이벤트를 정확히 정규화할 수 있게 requestId와 보상 확인 결과, 표시 여부, 종료 상태를 명확하게 설계하라.
- 스키마 v5의 progression에 `rewardedMissionIds: []`를 추가한다. DEFAULT_SCHEMA·docs/SAVE_SCHEMA.json·저장 형식 검사에 5를 추가하고 v2/v3/v4를 기존 필드 손실 없이 이전한다. ID는 실제 완료 미션 ID만 허용하고 중복/손상 값을 정규화한다.
- 코인 증가와 수령 ID 추가를 같은 상태 변경과 같은 payload에 담는다. 별도 키/서로 다른 저장으로 분리하지 않는다. 메모리 기록을 동기적으로 먼저 갱신해 빠른 중복 클릭·중복 콜백에서도 한 번만 지급한다. MAX_SAFE_INTEGER 보호와 기존 저장 실패 안내/후속 쓰기 복구를 보존한다.
- 저장이 실패해도 메모리 보너스를 다시 지급하지 않는다. 실패 상태를 안내하고 다음 정상 저장에 포함되도록 한다. 광고 no-fill/cancel/error/timeout/unavailable은 0코인이고 기본 진행을 막지 않는다. 타임아웃을 성공으로 간주하지 않는다.
- 결과 화면에서 떠나면 새 광고 요청을 취소/무효화한다. 이미 표시된 광고 중에는 입력과 결과 이동을 잠가 동일 결과를 유지한다. 콜백이 다음 미션의 상태를 바꾸지 않게 한다.

## 3. 전면 광고 정책

- 활성 플레이 120초, 누적 완료 2회, 마지막 전면 광고 이후 완료 3회, 모든 형식의 최근 표시 광고 이후 180초, 세션 최대 3회를 모두 만족해야 한다. 초기부터 완료 3회 조건도 적용한다. 모달/광고/백그라운드는 활성 시간에 포함하지 않는다. deltaSeconds를 활용하고 Date.now의 벽시계 변경으로 시간을 당기지 마라.
- 결과의 '다음 미션/샌드박스' 이동 의도가 발생한 경계에서만 확인한다. onImpact/조준/게임 중/상점/설정/Reset에서는 노출하지 않는다. 광고가 미준비면 기다리지 말고 이동한다. 늦은 로드 완료가 새 미션에서 광고를 띄우면 안 된다.
- 광고 제거 소유/권한 미확인/동의 미확인/오프라인/미지원이면 건너뛴다. 보상 광고 직후의 전면 광고는 180초 간격 때문에 차단한다. 기본 플랫폼의 ads 요청 허용 상태는 false다. 가짜 UMP/ATT 동의나 'iOS이면 true'를 쓰지 마라.
- 실제 표시가 확인된 광고만 횟수/간격에 반영한다. 한 번의 완료에서 여러 경로로 중복 광고를 띄우지 마라. 광고가 끝난 뒤 원래 이동을 정확히 한 번 수행한다. 지연 콜백/중복 클릭/앱 숨김에서 다른 의도를 실행하지 않는다.

## 4. 수명주기와 UI

- 실제 광고/구매 UI가 활성일 때 입력·시뮬레이션을 정지하고 진행 중 발사체는 보존한다. 오디오를 정지하고 제스처 상태를 비운다. 광고 종료 후 실제 document.hidden과 기존 모달 상태를 다시 평가해 재개한다. 광고 중 visibilitychange가 왔다고 게임을 재개하지 마라.
- UIManager.isBlockingInput 또는 공통 차단 조건에 수익화 busy 상태를 포함한다. 새 모달도 closeDialogs/Escape/포커스 복원을 지키되, 결제/광고 진행 중 Escape로 실행 잠금을 풀지 마라. 미지원/실패 시에는 잠금이 남지 않게 한다.
- 설정/안내가 미션을 종료하지 않는 규칙과 현재 탭/드래그/핀치 동작을 보존한다. 실패한 외부 서비스로 게임이 멈추거나 무한 로딩하지 않게 한다. 단, 네이티브 광고가 실제로 표시 중인데 단순 JS 타이머로 재생을 끝났다고 가정하여 입력 잠금을 풀지 마라.
- 390×844 세로, 844×390 가로, safe area, 키보드 접근, 최소 44px 터치 영역을 유지한다. textContent/createElement 기반 DOM 구성을 유지한다.

## 출력과 검증

변경/신규 파일 목록과 파일별 완성된 전체 코드를 제공하라. 변경 없는 파일은 출력하지 말고 부분 diff·생략·의사 코드는 쓰지 마라. 길면 파트로 나누고 남은 파일 목록을 명시하라. package-lock은 수정하지 마라. 실제 SDK가 구현되었다거나 테스트를 실행했다고 가정하지 마라.

Node의 의존성 주입 테스트를 제공하라. 테스트 성공 어댑터는 tests 안에서만 생성하고 main/runtime에서 import하지 않는다. 최소 항목: 미지원 무보상/무권한, 구매 취소/보류/미검증/복원 오류, 권한 미확인 시 전면 광고 금지, 보상 이벤트와 닫힘 양 순서, 중복/과거 콜백, 연속 클릭, 첫 완료 보상 저장 실패, 보너스 저장 실패, v2-v5 이전·보상과 ID 같은 스냅샷, 활성 시간 유예와 노출 간격/횟수, 보상 광고 직후 전면 광고 금지, 지연 로드/실패 후 잠금 해제, 다음 이동 1회, 기존 미션/상점/설정 보존을 확인하라. 실제 iOS SDK 검증은 후속 Mac 작업으로 남겨라.
