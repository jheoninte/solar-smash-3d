# 수익화 1차 구현 기준

## 범위와 현재 상태

현재 게임·저장·설정과 수익화 공통 흐름을 구현했다. `MonetizationController`, `AdPolicy`, 스키마 v5 보너스 원장과 상점·결과 UI를 연결했다. 플랫폼 구현은 unavailable이며 상품·광고 ID는 null, 광고 플래그는 false다. 실결제·실광고는 발생하지 않는다.

Gemini 초안 통합 후 광고 시도별 ID, 종료 시점의 콜백 차단, 구매 권한 응답의 최신성, 상품 조회 세대 분리와 입력 잠금을 보완했다. StoreKit 2·AdMob 어댑터와 Swift 소스도 통합했다. Windows에서 소스와 주입 테스트를 검증했고 최종 컴파일·실기기 검증은 Mac에서 진행한다.

## 상품과 무료 콘텐츠

| 항목 | 1차 기준 |
| --- | --- |
| 전면 광고 제거 | 비소모성 IAP 1개. 자동 전면 광고만 제거한다. 선택형 보상 광고는 유지한다 |
| 기존 코인 외형 | Earth 기본, Obsidian 250, Ember 450, Aurora 650 유지. 유료 구매로 바꾸지 않는다 |
| 유료 외형 팩 | 후속 범위. 기존 무료 외형과 별도 콘텐츠를 준비한 뒤 추가한다 |
| 판매용 코인·구독 | 1차에 추가하지 않는다 |
| 가격·스토어 ID | 미확정. 실제 상품 조회에서 받은 현지 가격만 표시하며 임의 가격은 표시하지 않는다 |

광고 설정이 없어 광고 제거 효과를 제공할 수 없거나, 스토어 상품/가격을 조회하지 못하면 구매 가능한 상품으로 제시하지 않는다. 미지원 환경에서도 기존 코인 상점은 계속 제공한다. 구매 복원은 별도 경로를 제공하고 취소·보류·실패를 성공과 구분한다.

구매 권한은 스토어가 검증한 어댑터 결과만 인정한다. JS localStorage/설정/URL의 불리언은 권한 근거가 아니다. 네트워크 오류를 환불/권한 소멸로 취급하지 않는다. 권한 확인이 미완료라면 전면 광고를 보여주지 않는다. 실제 환불·취소는 검증된 스토어 갱신으로 반영한다.

## 보상 광고

- 현재 결과 화면에 있는 첫 완료에 한해 선택할 수 있다. 기본 보상은 먼저 정상 지급하고, 광고를 보지 않아도 다음 미션/샌드박스로 진행할 수 있다.
- 보너스는 해당 미션 기본 보상의 50%를 내림한 코인이다. 미션 ID별 1회만 받을 수 있다. 재도전·목록·지형 복원·새로고침으로 제안을 재생성하지 않는다.
- 현재 6개 미션의 기본 코인은 총 1,650, 코인 외형 총가격은 1,350이다. 보너스 최대치는 825다. 콘텐츠 확장 전의 초기 경제 검증값이며 장기 소비처는 후속 밸런스 작업에서 조정한다.
- 광고가 준비됐고 요청이 허용된 경우에만 선택 버튼을 노출한다. SDK의 유효한 보상 이벤트가 없는 종료·취소·no-fill·timeout은 보상을 지급하지 않는다. show 호출 성공이나 시간 경과는 보상 근거가 아니다.
- 광고 요청 ID를 결과 화면의 제안과 연결한다. 중복/과거 콜백, 연속 클릭, 닫힘·보상 이벤트 순서 차이를 처리한다. 같은 제안의 재시도와 성공을 구분한다.
- 코인과 보너스 수령 기록을 스키마 v5의 같은 payload에 기록한다. `progression.rewardedMissionIds`를 추가했고 v2/v3/v4를 이전한다. 별도 설정 키와 두 번 저장해서 중복 지급을 막는 방식은 사용하지 않는다.
- 저장 실패 시 메모리에서는 한 번 지급하고 실패 안내를 유지한다. 첫 완료 보상을 저장하지 못했거나 읽기 보호 상태라면 광고 제안을 내지 않는다. 원본 보호와 이후 정상 저장의 복구 동작을 유지한다.

## 전면 광고

- 첫 120초의 실제 플레이와 초기 완료 2회를 보호한다. 이후에도 마지막 전면 광고 후 완료 3회, 모든 형식의 최근 표시 광고 후 180초, 세션당 최대 3회 조건을 모두 만족해야 한다.
- 실제 플레이 시간은 게임이 활성 상태이고 모달/광고로 일시 정지하지 않은 시간만 센다. 벽시계 변경·백그라운드·설정 화면 대기로 유예를 소진하지 않는다.
- 미션 결과에서 다음 미션/샌드박스로 이동하는 경계에서만 검토한다. 발사·조준·샌드박스 도중·설정·Reset·상점에 삽입하지 않는다. 보상 광고를 본 직후 전면 광고를 이어서 보여주지 않는다.
- 광고 제거 보유, 권한 미확인, 광고 미지원/미준비, 요청 동의 미확인, 오프라인이면 건너뛰고 사용자가 선택한 이동을 즉시 진행한다. 로딩이 늦게 끝나도 플레이가 시작된 뒤 표시하지 않는다.
- 전면 광고가 실제로 표시된 경우에만 노출 횟수와 간격 기준을 갱신한다. 중복 클릭/늦은 SDK 콜백이 여러 번 이동하거나 다른 미션으로 이동시키지 않아야 한다.

## 비용과 SDK 경로

- 초기 목표는 별도 백엔드·검증 서비스 월 사용료 없이 개발하는 것이다. IAP 후보는 StoreKit 2의 기기 내 검증과 currentEntitlements/거래 업데이트를 이용하는 직접 네이티브 어댑터다. 이 방식의 구현·유지보수와 Apple 계정/판매 수수료는 별개다.
- 광고는 AdMob 후보를 우선 검토한다. npm 조회에서 `@capacitor-community/admob` 8.4.1의 배포와 MIT 라이선스를 확인했다. 이는 core 8.6.2 호환성·네이티브 실행·공급자 약관/비용을 검증했다는 뜻은 아니다. 실제 어댑터 단계에서 README·SDK 요구사항·동의 API·iOS 지원을 확인하고 버전을 고정한다.
- Firebase·RevenueCat·유료 플러그인은 지금 도입하지 않는다. 추가 비용이나 서버가 필요해지면 이유와 가장 저렴한 대안을 비교한다.
- UMP 등의 광고 요청 가능 상태와 ATT의 실제 추적 여부를 다음 네이티브 단계에서 연결한다. 플랫폼이 iOS라는 이유만으로 요청 허용을 true로 만들거나 자체 가짜 동의창으로 대체하지 않는다. 기본값은 광고 요청 불가다.
- 상품·광고 ID와 실서비스 활성화는 최종 설정 단계다. 테스트 성공 어댑터는 Node 테스트에서만 주입하며 배포 게임에서 선택할 수 없게 한다.

## 작업 완료 구분

1. 정책 데이터·상세 구현 지시 작성 완료.
2. Gemini 결과 통합 완료: 상태 처리·공통 UI·보상 원장·광고 빈도 정책. `npm test` 15개 통과. 기본 플랫폼에서는 구매/광고 unavailable 유지. 브라우저에서 첫 보상·재도전·설정 복귀·외형 장착·재로드·모바일 상점을 검증했다.
3. 네이티브 소스 통합: StoreKit 2 로컬 플러그인, AdMob 8.3.0과 종료 프로토콜 보완, 테스트 전용 설정, UMP 동의·개인정보 옵션, 구매 복원/환불 갱신. 실제 SDK 실행 검증은 미완료.
4. Mac: Xcode 컴파일·실제 기기의 Sandbox 구매/복원/광고·권한·앱 복귀·개인정보 공개·TestFlight 검증.

## 네이티브 어댑터가 지켜야 할 계약

- 광고 동의·준비 상태는 캐시된 동기 boolean만 반환한다. 결과 화면 이동 중 동의나 로딩을 기다리지 않는다. 알 수 없으면 false다.
- 광고 `show*` Promise는 실제 네이티브 화면 종료와 보상 이벤트 정규화가 모두 끝나야 resolve/reject한다. raw close보다 보상이 늦게 올 수 있으므로 raw close만으로 종료를 선언하지 않는다. 표시된 광고를 JS 타이머로 해제하지 않는다. 실제 SDK의 이벤트 완료 보장을 확인해 구현한다.
- `onShown`은 실제 표시 시 호출한다. 보상이 없는 종료도 모든 광고 간격을 갱신한다. 보상은 활성 시청 시도 ID에 대해 SDK가 검증한 경우만 인정한다. 종료 후 이벤트는 무시한다.
- 구매 권한 전체 조회·복원은 완전한 검증 결과에만 `{status:'ok', verified:true, entitlements:[...]}`를 반환한다. 각 항목도 verified와 boolean owned가 필요하다. 검증된 빈 목록은 권한 소멸을 뜻한다. 오류·부분/미검증 목록은 권한을 취소하지 않는다.
- 읽기 전용 상품·권한 조회만 8초 후 종료할 수 있다. 구매·복원·광고의 외부 화면은 실제 종료를 기다린다. 거래 업데이트보다 이전에 시작한 쿼리의 응답은 권한을 덮어쓰지 않는다.
- 구매·광고 중 게임과 HUD·모달 입력·Escape·오디오는 잠근다. 다음 미션/샌드박스 이동은 1회이며 이동 완료까지 잠금을 유지한다. 재도전에는 전면 광고를 삽입하지 않는다.
- `docs/GEMINI_NATIVE_MONETIZATION_PROMPT.md`는 이번 네이티브 초안을 받은 작업 기록이다. 실 SDK 검증과 출시 완료는 주입 테스트 통과와 별개다.

## 네이티브 초안 통합 결과 (2026-11-17)

- npm에서 AdMob **8.3.0**의 MIT 라이선스·설치 소스를 확인하고 고정했다. 실제 package.json 의존성은 Capacitor core `^8.0.0`이다. SPM 매니페스트는 Google Mobile Ads **13.11.0**, UMP **3.1.x**, iOS 플랫폼 15를 선언한다. 이 선언이 Xcode 컴파일 성공을 의미하지는 않는다. 게임의 import map은 iOS 16.4 이상을 전제로 한다.
- 기본 런타임은 AdMob의 전체 JS ESM을 불러오지 않고 Capacitor `registerPlugin`으로 네이티브 메서드를 호출한다. AdMob 라이선스는 웹 번들에도 포함한다. 전체 ESM의 native-ad 전용 추가 의존성은 웹 import map에 노출하지 않는다.
- 초안의 JS 50ms 보상 드레인은 제거했다. `native/ios/AdMobOverrides/`의 최소 iOS 보완 소스로 요청 ID·광고 객체 identity·실제 표시 상태·보상 여부를 네이티브 메모리에서 묶고 dismiss/failure 때 한 번 반환한다. 표시 중 타이머 해제는 없다. `npm ci` postinstall이 원본 버전과 SHA-256을 검사해 적용하며 `native:check`는 적용 여부만 검사한다. SDK 업그레이드는 보완 소스 재검토가 필요하다.
- **현재 광고 범위는 iOS Google 직접 광고다. 미디에이션·Android 광고는 미지원**이다. Google 공식 [보상 광고 문서](https://developers.google.com/admob/ios/rewarded)는 Google 광고의 보상 콜백이 dismiss 전에 온다고 명시하지만 미디에이션의 순서는 공급자별로 다르다. 네이티브에서 이 순서로 캡처하므로 JS 브리지 이벤트 역순에 의존하지 않는다. 미디에이션은 별도 완료 계약 없이는 활성화하지 않는다.
- 네이티브 `getPresentationCapabilities` 버전 1이 확인되지 않으면 광고 supported/ready가 false다. 원본 플러그인의 조기 show Promise를 실수로 사용하지 않는다. 오래된 이벤트는 요청 ID 및 네이티브 광고 객체가 일치할 때만 처리한다.
- UMP 갱신/개인정보 화면은 직렬 실행하고 controller가 입력·Escape·오디오를 잠근다. 개인정보 변경 중 캐시된 광고는 무효화하고 늦은 preload 결과는 버린다. 동의 갱신 오류 시 요청 가능 상태는 false다. UMP의 canRequestAds는 개인화/추적 동의 자체와 다르므로 거절 후에도 제한 광고 요청이 가능할 수 있다.
- ATT는 자동으로 요청하지 않는다. 향후 추적 사용과 문구를 확정할 때만 선택적으로 연결하며, 요청 API는 void를 반환하므로 후속 상태 조회로 확인한다. UMP 양식에 포함된 ATT 동작은 실기기에서 확인한다.
- StoreKit 2 패키지는 npm 로컬 의존성 `solar-smash-store-kit`으로 등록했다. Capacitor 8.6.2의 실제 플러그인 탐색에서 `SolarSmashStoreKit` 이름으로 발견됨을 Windows 테스트로 확인했다. 조회 도중에는 부분 거래 이벤트를 발행하지 않으며, 완전한 검증 스냅샷을 수락할 때 이전 보유 상태와 비교해 변경·소멸을 알린다. 구매/환불 업데이트나 다른 스냅샷 수락과 겹친 조회는 최대 1회 재시도한다. 비소모성만 처리한다.
- 새 의존성 설치를 `npm ci --cache .cache/npm`으로 재현했고 미션 기록 통합 후 자동 테스트 총 **40개**가 통과했다. 현재 스키마 v6은 기존 v5 보상 원장을 보존한다. 테스트 성공 SDK는 tests 안에서만 주입한다. 실제 ID 설정·구매·광고·스토어 검증과 Xcode 빌드는 아직 수행하지 않았다.

## Gemini 검토 반영 (2026-11-17)

- 복원 응답보다 먼저 검증된 거래 업데이트가 도착해도 정상 복원을 오류로 표시하지 않는다. 더 최신인 환불·권한 철회가 있다면 오래된 복원 응답으로 되돌리지 않는다. 잘못된 상품 ID나 미검증 항목을 포함한 목록은 거부한다.
- Swift actor 경계는 Sendable 구조체로 전달하고, 브리지 딕셔너리 변환과 응답·이벤트 전달은 메인 큐에서 수행한다. 완전한 스냅샷의 상태 변경과 이벤트 발행은 actor 안에서 함께 처리해 동시 조회가 포그라운드 철회 알림을 없애지 않게 했다. 종료 후 지연된 관찰 시작도 차단한다. 실제 Swift concurrency 진단 통과 여부는 Mac에서 확인한다.
- 광고 브리지의 일시적인 초기 연결 실패는 재시도하며, 부분 등록된 리스너를 정리한다. 표시 결과의 프로토콜 위반은 네이티브 화면 종료를 보장할 수 없으므로 해당 어댑터 수명 동안 광고를 비활성화한다.
- 동의 세대가 바뀌어도 같은 형식의 SDK preload는 순차 실행한다. Gemini 초안의 세대별 병렬 preload는 적용하지 않았다. 기존 코드에서 주장한 loading 덮어쓰기는 재현되지 않았으며, 병렬화하면 오래된 네이티브 광고가 새 캐시를 덮어쓸 수 있다.
- 표시할 네이티브 광고는 present 직전에 준비 목록에서 소비한다. 이전 광고의 finish가 표시 중 새로 준비한 광고까지 삭제하지 않는다.
- 추가 주입 테스트는 복원 중 권한 업데이트·철회, 비정상 목록, 동기 초기화 예외와 부분 리스너 등록 실패 후 복구, 프로토콜 위반 후 재활성화 차단, 동의 갱신 중 preload 직렬화를 검증한다. Swift 실행 테스트를 대신하지 않는다.
