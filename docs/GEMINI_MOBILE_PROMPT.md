# Gemini 구현 요청: 모바일 조작과 플레이 피드백

> 이 요청은 통합과 Windows 검증을 완료했다. 아래는 원래 요청의 기록이며, 뒤에 붙는 소스는 통합된 최신 코드다. 같은 구현을 다시 수행하지 않는다. 현재 동작과 iPhone 미검증 항목은 `docs/MOBILE_CONTROLS.md`를 참고한다.

이 문서와 뒤에 붙은 현재 소스가 작업 기준이다. ZIP 대신 소스를 텍스트로 제공한다. 변경한 파일의 완성된 전체 코드만 반환하면 사용자가 Codex에 전달하여 통합·검증한다. 이번에는 아래 모바일 기능을 구현한다. 기존 플랫폼 저장·미션·상점은 이미 구현되어 있으므로 다시 설계하지 않는다. 읽지 않은 스킬 문서를 검토했다고 말하지 마라.

## 결과물과 범위

한 손가락/마우스 탭 공격, 드래그 회전, 두 손가락 핀치/휠 줌, 설정 다이얼로그, 짧은 사운드·선택형 햅틱, 첫 플레이 안내를 제공하라. iOS 우선·나중에 Android이며 Windows 브라우저 개발을 유지한다. 실결제·광고·랭킹·분석·서버·외부 미디어·계정 기능은 추가하지 마라. 네이티브 기능이 없는 브라우저에서도 게임은 동작해야 한다.

권장 분리(현재 API에 맞게 파일명 조정 가능): `src/input/GestureController.js`, 기존 `render/CameraController.js`, `src/audio/AudioManager.js`, `src/platform/haptics.js`, `src/settings/SettingsStore.js`. `main.js`는 조립과 콜백 연결에 집중한다.

## 1. 탭·드래그·줌

- 기존 pointerdown 즉시 발사를 제거하고 GestureController의 유효한 탭 콜백에서만 기존 Raycast→WeaponSystem 경로로 발사한다. pointerup까지 시작점에서 8 CSS px를 한 번도 넘지 않고 350ms 이하인 단일 기본 포인터만 탭으로 인정한다. 장거리 이동 후 원위치로 돌아와도 탭이 아니다.
- canvas에만 Pointer Events를 연결한다. 마우스 왼쪽 드래그/한 손가락 드래그는 원점 중심 궤도 회전, 두 손가락은 핀치 줌, canvas의 휠은 줌이다. pan과 자동 회전은 이번 범위가 아니다.
- 두 번째 포인터가 들어오면 해당 제스처의 탭 후보를 전부 무효화한다. 핀치 후 남은 손가락을 떼도 발사하지 않는다. 모두 뗀 뒤 새 pointerdown부터 탭이 가능하다.
- pointer capture, pointercancel, lostpointercapture, 창 blur/탭 숨김, 모달 열기, 모드 전환, Reset에서 입력 상태를 정리한다. 취소/정리 때문에 공격하지 말고 리스너와 capture가 남지 않게 한다. UI 버튼/모달 입력은 canvas 조작으로 전달하지 않는다.
- 입력의 픽셀 이동량은 뷰포트 크기로 정규화한다. 이미 이벤트 이동량에 반영된 값을 다시 deltaTime으로 곱하지 않는다. 관성/보간을 추가한다면 deltaTime을 사용한다. 관성 없이 안정적인 직접 조작도 허용한다.
- 기존 카메라의 초기 시야를 유지하되 yaw/pitch/zoom 상태를 갖게 한다. pitch 극점 제한과 안전한 최소/최대 거리를 둬 천체 내부 진입을 방지한다. 줌은 기본 fit 거리의 약 0.7~2.4배 범위로 제한하되 모드의 전체 bounding radius보다 충분히 멀게 한다. resize 시 aspect/fit 기준은 갱신하고 사용자가 선택한 방향/줌 비율은 유지한다. 모드 변경·Reset은 초기 카메라로 복귀한다.
- camera 위치/방향을 바꾸면 행렬을 갱신해 회전 후에도 현재 화면에서 고른 천체에 정확히 명중해야 한다. Planet/Solar 모두 지원한다.

## 2. 설정과 설정 저장

- 작은 설정 버튼과 native `<dialog>`를 추가한다. 사운드 on/off, 음량 0~100%, 햅틱 on/off, 조작 안내 다시 보기, 카메라 초기화, 닫기를 제공한다. 한국어 label과 최소 44px 터치 영역, aria 상태·키보드·Escape·포커스 복원을 구현한다.
- 설정/안내를 여는 동안 입력과 시뮬레이션을 정지하되 미션·발사체·진행도를 종료/초기화하지 않는다. 기존 상점/미션 목록의 미션 종료 정책은 유지한다. 새 모달의 cancel을 기존 onMissionExit에 잘못 연결하지 마라. `closeDialogs`와 `isBlockingInput` 및 입력 취소를 새 모달까지 일관되게 확장한다.
- 기본값: soundEnabled=true, volume=0.35, hapticsEnabled=true, tutorialDismissed=false. 사운드는 실제 사용자 제스처로 오디오가 해제된 뒤에만 재생한다. 햅틱 미지원이면 토글 설명에 표시하고 나머지 설정은 쓸 수 있게 한다.
- 게임 스키마 v4와 게임 저장 키 `solar-smash-3d.save`는 유지한다. 별도 키 `solar-smash-3d.settings.v1`에 `{ settingsVersion: 1, soundEnabled, volume, hapticsEnabled, tutorialDismissed }`를 저장한다. 카메라 방향과 제스처 상태는 저장하지 않는다.
- 기존 StorageAdapter는 게임 세이브 전용 parseSave 검사를 한다. 설정 객체를 그대로 load하면 오류로 차단된다. `load(key, { validate } = {})`처럼 키마다 검증기를 주입할 수 있도록 최소 확장하고, 기본 검증은 기존 v2/v3/v4 게임 검증을 유지하라. 설정 검증은 자기 버전과 객체 형식을 검사하고 개별 값은 정규화한다. 알 수 없는 버전·읽기/파싱 실패는 덮어쓰지 않는다.
- 설정도 같은 주입된 StorageAdapter의 순간 JSON 스냅샷/순차 큐/실패 복구/원본 보존을 사용한다. 직접 localStorage·Preferences를 중복 호출하는 두 번째 저장 엔진을 만들지 마라. 게임 키와 설정 키의 쓰기 허용·오류 상태는 독립적으로 유지한다. 한쪽 손상으로 다른 쪽 저장을 차단하지 마라.
- 설정은 변경 즉시 메모리에 반영하며 저장 대기/실패는 설정 안에서 표시한다. 저장 실패여도 실행 중 설정은 작동한다. GameStateStore의 게임 저장 상태를 설정 저장 성공으로 덮어쓰지 마라.

## 3. 사운드와 햅틱

- 외부 음원·CDN·생성 에셋 없이 Web Audio로 짧은 무기 발사/명중/미션 완료 효과음을 합성하라. 배경음악은 이번 범위가 아니다. 무기 3종의 소리를 구분하되 짧고 과도하지 않게 한다.
- AudioContext는 실제 사용자 제스처에서 생성/resume하고 reject를 처리한다. 자동재생 거부나 오디오 미지원으로 게임 시작이 실패하면 안 된다. 첫 탭에서 명중할 때까지 오디오 해제가 정상 이어지게 한다.
- master gain으로 음량과 mute를 적용하고 동시 발성 수(예: 최대 8개)를 제한한다. 종료한 oscillator/source/gain을 해제하며 반복 타격에서 노드가 무한 누적되지 않아야 한다. 탭 숨김/복귀·설정 모달·dispose의 suspend/resume을 처리한다. 백그라운드 효과음을 큐에 모아 복귀 시 한꺼번에 재생하지 마라.
- 햅틱은 플랫폼 서비스로 주입한다. 검증된 패키지 후보는 `@capacitor/haptics@8.0.2`이며 core >=8과 호환된다. 네이티브 플러그인의 실제 존재를 `isPluginAvailable` 등으로 확인한다. 브라우저는 기본 unavailable/no-op이며 가짜 진동 성공을 표시하지 않는다.
- 햅틱 off와 빈 공간 탭은 진동하지 않는다. 유효한 새 명중/미션 완료 시에만 약한 피드백을 주고 약 80ms 이상 호출 간격을 둔다. 플러그인 미지원/reject/오프라인이 게임을 깨뜨리지 않게 한다.
- 무기 발사·새 impact·미션 완료에 연결한다. 저장된 지형 복원·재장착·모드 재생성에서 소리/진동/보상을 재발생시키지 마라. 한 impact당 구독자는 한 번만 처리하며 unsubscribe/dispose를 제공한다.
- Haptics 의존성을 추가한다면 package.json, import map, scripts/vendor-assets.mjs, dev/build/check 경로와 라이선스까지 제공하라. 패키지 버전이 core와 같다고 가정하지 말고, 확인 없이 존재하지 않는 8.6.2를 쓰지 마라. 잠금 파일은 Codex가 npm으로 생성한다. 현재 정적 ESM 구조를 유지하고 Vite 전환·원격 URL·런타임 node_modules 경로는 쓰지 마라.

## 4. 첫 플레이 안내

- 첫 실행에 건너뛸 수 있는 한 화면 안내: '가볍게 탭해 공격', '드래그해 회전', '두 손가락/휠로 확대·축소', '미션 첫 완료 코인으로 외형 구매'. 시작 버튼으로 닫으며 tutorialDismissed를 설정 키에 저장한다. 초기 안내는 게임 입력을 차단하고 그 아래 canvas에 발사가 전달되지 않게 한다.
- 설정에서 다시 열 수 있다. 새로고침 후 안내 완료 상태를 복원하며 게임 Reset은 이를 지우지 않는다. 설정 저장 실패 시 이번 실행에서는 안내를 반복해서 띄우지 않는다.
- 390×844 세로와 844×390 가로, safe area, 긴 한국어 문구, 스크롤, 키보드 접근을 고려한다. 현재 5개 상단 버튼에 버튼을 추가해도 화면 밖으로 넘치지 않게 한다.

## 이미 검증된 동작: 반드시 보존

- `GameStateStore.loadGame()`은 state를 반환하며 store.state는 없다. 게임 코어는 SDK를 가져오지 않는다. main에서 `createPlatform()`→storage 주입으로 조립한다.
- persist는 Promise<boolean>이다. 구매/장착/미션 보상은 메모리를 동기 갱신한 결과와 `whenSaved`를 반환한다. Promise를 성공 boolean으로 사용하거나 화면 전환을 저장 완료까지 지연시키지 마라.
- 저장 큐는 호출 즉시 JSON을 고정한다. 읽기 실패는 빈 데이터가 아니며 덮어쓰기를 차단한다. 네이티브 기존 데이터 우선, native=null일 때만 같은 WebView의 로컬 데이터 이전, 원본 삭제 금지, 실패 후 다음 쓰기 복구를 유지한다.
- HubGame은 로컬 저장·미션·상점의 조건이 아니다. HubGame이 없다는 이유로 이 기능이나 오류 안내 DOM을 제거하지 마라.
- 미션 6개·첫 완료 보상·코인 외형 4종·기존 세이브 v2/v3→v4·최근 120개 타격 복원을 유지한다. Reset은 코인/외형/미션 기록을 지우지 않는다. 기존 파괴/지형/효과를 새로 작성하지 마라.
- `runId`는 런타임 전용이다. `flushCompletion()`은 weapons.update/이벤트 순회 후 실행하고 순회 중 발사체 배열을 비우지 마라.
- iOS 실기기 검증은 추후 Mac에서 한다. Windows 코드 검증을 iPhone 실행 검증이라고 주장하지 마라. 실제 IAP/광고/랭킹은 unavailable 상태를 유지한다.

## 출력 형식과 검증 조건

먼저 변경/신규 파일 목록을 주고 각 파일의 **완성된 전체 코드**를 경로별 코드블록으로 제공하라. 변경 없는 파일은 재출력하지 마라. 부분 diff·생략·의사 코드 금지. 답변이 길어지면 논리적인 파트로 나누고 계속 필요한 파일 목록을 명시하라. API가 서로 다른 두 대안을 섞지 마라.

검증 가능한 짧은 테스트/수동 체크를 함께 제공하라: 탭 1회=발사 1회, 드래그/핀치/장기 누름/취소=발사 0회, 핀치 뒤 새 탭, UI 중 입력 차단, 모달 중 진행 미션 보존, 회전 후 Raycast, resize와 줌 제한, 리스너 정리, 음소거/음량·최대 동시 음원·백그라운드 복귀, 햅틱 미지원/reject/off, 설정 키의 순차 저장/이전/손상 보호·게임 키 독립, 첫 안내 1회와 다시 보기, 기존 미션/상점 회귀. 실행하지 않은 테스트는 실행했다고 하지 마라.
