# 모바일 조작과 플레이 피드백

## 구현

- 기본 공격: 하단 52px 자동공격 버튼으로 켜기/끄기. 가려지지 않은 플레이 공간 가운데 조준점으로 Raycast하며 운석 700ms·레이저 450ms·미사일 1100ms 간격이다. 현재 레이저는 간격 타격이며 연속 빔 연출은 후속 작업이다.
- 프레임 지연 후 밀린 발사를 몰아서 실행하지 않는다. 빗나가면 100ms 이내 간격으로 재시도한다. 수동 탭도 유지하며 기존 피해량/첫 완료 보상/별 기준/저장 스키마는 바꾸지 않았다.
- 메뉴·설정·안내·미션 완료·모드 전환·Reset·blur·페이지 숨김에서 자동공격을 끈다. 복귀 후 사용자가 다시 켠다. 이미 비행 중인 발사체는 중지 버튼 후에도 명중할 수 있다.
- 미션 상세 설명/종료 버튼은 펼침 영역에 배치한다. 저장 성공 안내는 상점/결과에 두고 HUD에는 저장 오류를 표시한다. 상점과 결과창에는 가장 저렴한 미보유 외형의 코인 목표/구매 가능 상태와 다음 미완료 미션을 표시한다. 코인 지급·가격은 바꾸지 않는다.
- 탭: canvas를 350ms 이내, 시작점에서 최대 8 CSS px 안에서 눌렀다 떼면 공격한다. pointerdown에는 발사하지 않는다.
- 드래그: 한 손가락/마우스로 원점 주위를 회전한다. 한 번이라도 이동 한도를 넘으면 원위치로 돌아와도 발사하지 않는다.
- 핀치/휠: 줌 비율을 기본 fit 거리의 0.7~2.4배로 제한한다. 천체 bounding radius의 1.35배보다 가까이 접근하지 않는다. 두 포인터 제스처는 모두 뗀 뒤 새로 눌러야 다시 탭이 가능하다.
- pointercancel·capture 상실·blur·탭 숨김·모달·모드 변경·Reset은 입력 상태를 정리한다. resize는 방향/줌 비율을 유지하고 카메라 초기화·모드 전환·Reset은 초기 시야로 돌아간다.
- 설정과 조작 안내는 미션과 발사체를 보존한 채 시뮬레이션을 정지한다. 닫기/Escape 후 같은 런을 이어간다. 상점/미션 목록의 기존 미션 종료 정책은 유지한다.
- 첫 안내는 닫기/Escape 후 완료로 기록되며 설정에서 다시 볼 수 있다. 다시 보기에서 닫으면 설정으로 복귀한다.

## 별도 설정 저장

`SettingsStore`는 같은 `platform.storage`를 사용하고 `solar-smash-3d.settings.v1`에 저장한다. 기본값은 `{ settingsVersion: 1, soundEnabled: true, volume: 0.35, hapticsEnabled: true, tutorialDismissed: false }`다. 음량은 내부 0~1, UI 0~100%로 변환한다. 0을 기본값으로 덮어쓰지 않는다.

`StorageAdapter.load(key, { validate })`의 선택적 검증기로 설정 형식을 읽는다. 옵션이 없으면 기존 게임 v2/v3/v4 검증을 그대로 사용한다. 두 키의 읽기 실패 보호는 독립적이고 순차 쓰기 큐는 공유한다. 게임 스키마 v4, 코인·미션·외형 데이터는 변경하지 않았다. 설정을 변경하면 즉시 실행에 반영하고 저장 상태는 설정 다이얼로그에 표시한다.

## 사운드와 햅틱

- Web Audio는 실제 pointerdown/keydown에서만 생성·해제(resume)를 시도한다. 지원하지 않거나 자동재생이 거부되어도 게임은 계속 동작한다.
- 무기 발사 3종·새 명중·미션 완료의 짧은 합성 효과음만 사용하며 외부 파일/음악은 없다. 동시 음원은 최대 8개다. ended·mute·설정/안내·탭 숨김·dispose에서 노드를 정리한다. 일시 정지 중 소리를 모아 두지 않는다.
- 미션 결과 화면에는 완료음을 낼 수 있다. 설정/안내를 보는 동안 효과음은 정지한다. 완료음의 실제 청감과 iPhone 오디오 정책은 추후 실기기에서 확인한다.
- Haptics 8.0.2를 core 8.6.2와 사용한다. 네이티브 환경에서 플러그인이 실제 등록된 경우에만 지원으로 표시한다. 브라우저는 unavailable이며 navigator.vibrate를 사용한 성공 대체 동작은 없다.
- 햅틱은 약한 명중/완료 피드백이며 80ms 간격, 동시 호출 1개로 제한한다. 250ms 넘게 지연된 요청, 설정 off/숨김/폐기 이후의 요청은 버린다. 플러그인 실패는 게임으로 전파하지 않는다. 저장 지형 복원은 impact를 재발행하지 않으므로 소리/진동도 재생하지 않는다.

## Windows 검증과 Mac 인계

자동공격 추가 검증: 45개 Node 테스트, 저장소 검사, 정적 빌드/네이티브 웹 번들 검사를 통과했다. Windows 인앱 브라우저의 320×740 세로/740×320 가로에서 큰 토글·패널 배치·미션 상세 펼침/종료를 확인했다. 자동 레이저 미션 완료·결과창의 수집 목표·메뉴에서 정지 후 복귀 시 꺼짐·중지 버튼 후 명중 수 유지·드래그 오발사 없음·수동 탭 명중을 확인했고 브라우저 오류 로그는 없었다. 장시간/저사양/iPhone 성능은 이 검증에 포함하지 않았다.

코드 테스트로 탭/드래그/핀치·취소·capture·정리, 카메라 제한/resize, 설정 형식·순차 저장·오류·키 독립성, 음원 수 제한/해제, 햅틱 지연/실패를 검증했다. 브라우저에서는 드래그 오발사 방지·회전 후 탭 명중, 미션 중 설정/안내 진입·복귀, 새로고침 후 음소거/음량 0/안내 완료 복원을 확인했다.

실제 멀티터치, 오디오 청감·무음 스위치·전화/오디오 중단·복귀, Core Haptics의 기기별 반응, 성능은 Mac 인계 후 iPhone에서 검증한다. 자동 코드 테스트를 실기기 검증으로 표현하지 않는다.
