# Gemini 구현 요청: 기존 미션의 별점·로컬 최고기록

작업 상태: 이 구현은 통합·검증을 완료했습니다. 현재 재생성한 묶음은 작업 기록과 최신 소스 참고용입니다. 새로운 요청 없이 같은 기능을 다시 구현하지 마세요. 최종 기준과 검증 결과는 `docs/MISSION_REPLAY_PLAN.md`를 따릅니다. 아래는 원래 구현 요청입니다.

첨부한 `===== FILE: ... =====` 이후의 실제 최신 파일을 기준으로 구현해주세요. 과거 대화나 예전 초안으로 파일을 되돌리지 마세요. 이번에는 기존 6개 미션의 재도전 루프만 구현합니다. 대규모 초안은 Gemini, 코드 검토·통합·검증은 Codex가 담당합니다. Windows에서 개발하고 최종 Xcode/iPhone/TestFlight만 이후 Mac mini에서 진행합니다.

`docs/MISSION_REPLAY_PLAN.md`가 이번 범위와 평가·저장·UI 기준입니다. 해당 문서에 정한 시간 기준은 초기 임시값이며 플레이테스트했다고 주장하지 마세요. 제공되지 않은 `game-studio.md` 등의 지식 파일을 실제 읽었다고 쓰지 마세요. 외부 파일 없이 현재 소스로 Vanilla Three.js 모듈 구조를 유지하세요.

## 구현해야 할 것

1. 미션 정의에 2성/3성 시간 기준을 추가하고 순수 평가 함수를 분리하세요. 완료하면 최소 1성이고 시간 초과 실패는 없습니다. 기존 목표·6개 ID·보상·무기 데미지·발사 동작은 보존하세요.
2. MissionSystem에 주입 가능한 단조 증가 시계와 런별 활성 시간·일시정지/재개를 추가하세요. `Date.now()`나 렌더링 clamp delta 누적을 사용하지 마세요. 지연 프레임에서도 실제 전경 플레이 시간이 기록에 들어가야 합니다. 메뉴/백그라운드는 제외하고 비행·조준 시간은 포함하세요. 시간은 목표 달성 시 고정하고 스냅샷으로 넘기세요.
3. main.js의 기존 입력·모달·수명주기 흐름에 통합하세요. 정지/재개 경계를 명시적으로 처리하고 겹친 정지 사유 중 하나만 해제되어도 다른 사유가 있으면 계속 정지해야 합니다. 레이저는 fireWeapon 안에서 동기 impact를 발행하므로 프레임 콜백만 의존하지 마세요. 시작/재도전/종료 때 시계와 runId를 정리하고 이전 런 impact를 무시하세요. getSnapshot만 호출해서 완료 시간이 증가하면 안 됩니다.
4. SAVE_SCHEMA.json과 state.js의 fallback을 함께 v6으로 올리고 `progression.missionRecords[id] = { bestActiveMs }`를 저장하세요. storage.js의 버전 허용 목록에도 v6을 반영하세요. v2~v5 이전, 손상·미래 버전 보호, 순차 불변 스냅샷, 설정 키 독립성을 유지하세요. 기록의 유효성은 안전한 양의 정수 밀리초로 검증하세요. 유효한 측정이 없는 레거시 completion 호출은 기존 첫 완료 보상을 처리하되 시간 기록은 만들지 마세요. 기존 테스트 호환을 위해 존재하지 않는 시간을 0초 최고기록으로 생성하지 마세요.
5. 목표 달성 검증과 첫 완료 보상 처리는 기존 claimMissionReward 경로를 보존하세요. 검증된 완주 시간일 때만 최소 기록을 갱신하고 이번 결과·이전 최고·갱신 여부를 UI에 전달하세요. 중복 완료 호출로 돈이 늘면 안 되며 느리거나 같은 시간의 재도전은 최고기록을 갱신하지 않습니다. 기록 갱신과 첫 완료는 서로 다른 상태입니다.
6. HUD에 활성 시간, 미션 목록에 최고 별/시간, 결과 화면에 이번 기록·최고기록·다음 별 기준/3성 이후 시간 단축 목표를 추가하세요. 첫 기록은 '첫 기록', 이후 개선만 '최고기록 갱신'으로 구분하세요. 시간 비교는 정수 밀리초이고 표시는 읽기 좋게 반올림하되 경계 근처에서 달성 조건을 잘못 안내하지 마세요. 설명은 한국어로 쓰고 레이아웃을 320px 모바일 폭에서도 사용할 수 있게 하세요. 별 표시는 접근 가능한 텍스트를 포함하세요. 새 결과 영역이 광고 상태 갱신으로 사라지지 않게 하세요.

## 유지해야 할 계약

- 첫 완료 보상은 기존 1회이며 반복 보상·별점 코인·유료 별점·새 IAP를 추가하지 않습니다. 첫 완료 합계는 1,650코인입니다.
- result의 `mission`, `reward`, `isFirst`, `whenSaved` 계약과 광고 보상 원장 `rewardedMissionIds`를 유지하세요. 기록 개선을 isFirst=true로 취급하거나 광고 기회를 재생성하지 마세요.
- MonetizationController/AdPolicy/설정/플랫폼 SDK는 참고용입니다. 해당 소스나 수익화 정책을 재작성하지 마세요. 기본 광고/상품 ID null/off, 미지원 환경 무구매/무광고/무보상, 외부 화면 중 입력·오디오 잠금은 유지하세요.
- HubGame 전용 UI의 조건부 노출, 샌드박스, 코인 외형 상점·지형 보존, 설정/안내 중 미션 보존을 유지하세요. 점수·기록을 클라우드에 제출하지 않습니다.
- 새 서버·Firebase·Game Center·추가 npm 패키지·번들러·분석 SDK·날짜/일일 보상·새 미션·무기 쿨다운은 이번 범위에 없습니다. 네이티브 Swift/AdMob 보완 소스는 수정하지 마세요.

## 테스트와 응답 형식

Node 내장 테스트와 주입 시계로 아래 행동을 검증하세요. 구현을 그대로 복사하는 테스트나 Swift를 실행한 것처럼 보이는 가짜 테스트는 만들지 마세요.

- 3성/2성 기준 바로 전·정확한 경계·바로 후, 시간 초과 1성, 완료 전/잘못된 시간 거부.
- 활성 플레이와 느린 프레임의 실제 경과시간 포함, 설정/안내·숨김·수익화 화면 제외, 겹친 정지 사유, 완료 후 시간 고정, 재도전/이전 런 영향 차단.
- 빠른 재도전만 기록 갱신, 동률/느린 재도전 보존, 최초 보상·광고 보너스 원장 중복 방지.
- v2/v3/v4/v5→v6 진행도 보존, v6 기록 복원·필드 정규화, 손상/미래 버전 원본 보호, 지연·실패 저장에서 순차 스냅샷 보존.

기존 `tests/monetization.test.mjs`의 예상 버전은 필요한 곳만 v6으로 바꾸고 v5 이전 사례를 추가하세요. 테스트를 삭제하거나 약화하지 마세요. 실제 실행할 수 없는 환경이면 미실행이라고 쓰세요. Codex가 최종적으로 `npm test`, `npm run check`, `npm run native:prepare`와 브라우저 QA를 실행합니다. 현재 테스트 총 33개에는 네이티브 어댑터 테스트도 포함되어 있지만 이번 소스 묶음은 토큰 절약을 위해 관련 공통 테스트만 포함합니다.

응답은 짧은 변경 요약, 변경·추가한 파일 목록, **그 파일들의 완성된 전체 코드**, 테스트/미검증 사항 순서로 주세요. 경로를 정확히 쓰고 생략·의사 코드·일부 diff·'나머지는 동일' 표기는 쓰지 마세요. 변경하지 않은 파일이나 네이티브 소스를 다시 출력하지 마세요. 문서 개정과 최종 통합은 Codex가 담당합니다.
